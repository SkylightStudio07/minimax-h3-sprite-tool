# 포즈 기반 걷기·달리기 생성 · 종료된 실험 기록

## 종료 상태 (2026-10-18)

사용자가 영상 기반 결과를 선택하여 **프레임별 포즈 생성 기능은 종료했습니다.** 캐릭터 작업실·프레임 편집기·메인 가이드에서 진입점을 제거하고 `/motion-studio`는 영상 스프라이트 도구로 이동합니다. `/api/motions`, `/templates`, `/poses`의 새 생성/템플릿 요청은 로그인 후 HTTP 410입니다. 기존 상태 조회와 생성된 프레임 작업·버전·내보내기는 유지합니다. 이미지 원화 생성의 단일 포즈 편집, Live2D 뼈대 편집, Qwen 부분 수정은 별도 기능이며 유지합니다.

현재 경로는 **스프라이트 시트 → 세팅 모음 → 걷기/달리기 영상 테스트 세팅**입니다. 영상 생성 후 프레임 편집기의 구간 미리보기·잘라내기로 루프를 정리합니다. 아래 내용은 당시 실험의 인계 기록입니다.

## 이전 실험 사용법

**캐릭터 작업실 → 포즈로 동작 만들기** 또는 `/motion-studio`에서 엽니다. 기존 영상 생성 방식과 별개의 경로입니다.

1. 캐릭터 묶음의 대표 원화를 가져오거나 직접 업로드합니다. 유지할 머리·의상·장비를 설명합니다. 가능하면 전체 몸과 발이 보이고 생성할 방향에 가까운 원화를 사용하세요.
2. **걷기 / 달리기**를 먼저 선택하고 방향, 프레임 수, 보폭을 조절합니다. 기본은 8장입니다. 걷기는 한 발 지지·체중 이동·반대 팔 스윙, 달리기는 전경 자세·굽힌 팔·높은 무릎·두 발이 뜨는 구간을 갖습니다. 동작을 바꾸면 보폭과 FPS도 해당 동작 기본값(8장 기준 걷기 보폭 12/8FPS, 달리기 보폭 17/12FPS)으로 바뀝니다. 프레임 수를 바꾸면 기본 FPS도 비례하여 조절하며, 직접 지정한 FPS는 유지합니다. 두 동작은 별도 작업과 클립으로 생성하며 내보내기 ZIP은 sprite-walk-v1.zip / sprite-run-v1.zip처럼 구분합니다. 기본 **원화 보존 편집**은 첫 프레임을 공통 외형 기준으로 사용합니다. **기존 방식 · 그림체로 다시 생성**을 선택하면 예전처럼 그림체와 변형 강도를 지정할 수 있습니다. 보폭 변경은 포즈에 바로 반영됩니다. **현재 설정으로 템플릿 다시 배치**로 수동 편집한 관절을 초기화할 수 있습니다.
3. 프레임을 선택하고 관절을 드래그해 캐릭터 비율에 맞춥니다. 관절 선택 목록, Ctrl/Cmd+Z, 프레임 ←/→, 선택 관절 ↑/↓ 이동을 지원합니다. **포즈 재생**으로 팔·어깨·골반까지 포함한 동작 순서를 확인합니다.
4. 크기·FPS를 조절하고 **동작 프레임 생성**을 누릅니다. 원화 보존 편집은 원화의 그림체를 사용합니다. 기존 방식에서만 별도 그림체·포즈 변형 강도가 적용되며, 강도가 높으면 포즈를 더 따르지만 원래 디자인이 달라질 수 있습니다.
5. 한 프레임씩 순차 생성하므로 일반 원화 한 장보다 오래 걸립니다. 페이지를 이동해도 작업은 계속되며 같은 탭의 **이전 작업 진행·결과 확인**으로 돌아올 수 있습니다. 실행 전 대기 상태에서는 **대기 작업 취소**가 가능합니다.
6. 전부 성공하면 **생성 프레임 편집기로**에서 재생·고정·부분 수정·버전 복원·ZIP 내보내기를 이어갑니다. 묶음에서 시작했다면 **프레임 수정본**에도 걷기/달리기 이름을 구분하여 표시합니다.

## 현재 품질 범위

이 기능은 시간축을 함께 생성하는 영상 모델이나 전용 모션 전이 모델은 아닙니다. 현재 기본 경로는 **공통 외형 기준 + 목표 포즈 이미지로 편집**하는 방식입니다. 기존 ControlNet 단독 경로보다 의상 보존을 우선하지만, 얼굴·가려진 장비·손 모양이 달라지거나 포즈를 약하게 따를 수 있습니다. 첫 프레임부터 외형이 틀리면 이후에도 잘못된 디자인이 유지될 수 있습니다. 현재는 프레임 초안을 생성·검토하는 실험 도구이며 바로 게임에 넣을 완성 걷기를 보장하지 않습니다.

- **원화 보존 편집**: 최초 원화로 첫 프레임을 만든 뒤, 그 첫 프레임만 모든 후속 프레임의 공통 기준으로 사용합니다. 직전 프레임을 계속 물려주지 않습니다. 원화 참고 이미지와 목표 포즈 이미지를 별도 입력으로 전달하고, 걷기 단계도 텍스트로 지정합니다. 프레임 편집기에 첫 프레임을 **외형 기준**으로 표시합니다. 첫 프레임을 편집기에서 나중에 수정해도 이미 생성한 다른 프레임에 자동 전파되지는 않습니다.
- **기존 방식**: 모든 프레임이 최초 원화를 참고하고 같은 seed를 사용합니다. 이 경로의 최초 실제 테스트에서는 프레임마다 코트·장갑·바지가 달라졌으며, 강도를 낮춰도 디자인 변화가 남았습니다.
- 최초 원화만 비율을 유지하여 캔버스에 배치합니다. 생성 프레임은 AI 배경 제거 후 **고정 캔버스의 위치와 크기를 유지**합니다. 이전처럼 각 프레임의 실루엣을 같은 높이·바닥선으로 다시 맞추면 몸의 상하 이동·달리기의 공중 구간까지 지워지므로 이 정렬을 제거했습니다. 모델이 만든 크기 흔들림이나 발 미끄러짐을 자동 교정하는 기능은 아닙니다.
- 얼굴·의상 내부의 작은 차이는 기존 프레임 편집기로 수정할 수 있습니다. 전신 의상이 크게 달라지면 부분 수정만으로 해결하기 어렵습니다. 변형 강도 조절, 방향에 맞는 원화 준비, 포즈 수정 후 재생성이 필요합니다.
- 4/8장은 마지막에 첫 포즈를 중복하지 않는 제자리 동작 주기입니다. 4장은 거친 확인용이고 8장을 권장합니다. 어깨와 골반의 반대 움직임·몸통 상하 이동·굽힌 관절을 템플릿에 포함합니다. 뼈대 포즈가 좋아도 이미지 모델이 그대로 따르거나 시간적으로 연결된다는 보장은 없습니다. FPS는 내보내기 메타데이터에 저장합니다.
- 원화·이전 동작을 변경하지 않습니다. 프레임 일부가 실패하면 새 프레임 작업을 게시하지 않습니다. 실패 기록과 기준 원화는 서버 데이터 폴더에 남습니다.

## 구현·권한

- `pose_motion.py`: COCO-18 걷기·달리기 템플릿, 입력 검증, 기존 `image_engine` 참고 이미지+ControlNet 실행, 최초 원화 정렬·생성 캔버스 보존, 완료된 프레임 작업 게시.
- `web/motion-studio.html`, `web/assets/motion-studio.js`, `.css`: 원화/설정, 프레임별 관절, 재생, 상태 추적.
- `motion_identity.py`: Qwen Image 2.1에 원화와 목표 포즈를 별도 참고 이미지로 전달합니다. 입력·출력 임시 파일 정리, CPU prefix cache, 배경 제거를 사용합니다. 원화 보존 경로는 별도 그림체 LoRA를 추가하지 않습니다. 설치된 Qwen 가중치와 배경 제거 모델을 재사용하며, 기존 모델의 이용 조건이 유지됩니다.
- 기존 방식은 `flanime-xl` 또는 셀 채색 전투 혼합과 `illustrious-openpose-v1.safetensors`를 사용합니다. 새 모델 다운로드는 없습니다. 해당 모델/LoRA의 기존 이용 조건이 유지되며 상업 허용을 새로 부여하지 않습니다.
- `/api/motions/templates`: 준비 상태와 walk4/walk8/run4/run8. `/api/motions/poses?action=walk|run&count=4|8&facing=left|right&stride=.12`: 실제 편집 템플릿. 프론트는 이 API를 사용하며 포즈 공식을 중복 구현하지 않습니다. `POST /api/motions`: 생성 등록. `GET /api/motions/<task>`: 소유자/관리자 상태 확인.
- `jobType=pose-motion`은 기존 FIFO 워커에서 순차 실행하며, 다른 Comfy 큐가 동작 중이면 대기합니다. `consistency=reference-edit`는 리깅 Comfy(8190), `independent`는 이미지 Comfy(8189)를 사용합니다. 변경 전 등록된 작업은 consistency 필드가 없으면 기존 방식, action 필드가 없으면 걷기로 실행합니다. 새 작업의 action은 walk/run이며 clips.name과 motion.action에 보관합니다. template은 walk-v2/run-v2입니다. 원화 보존 편집 전 다른 프로세스의 모델을 비우고, 각 프레임 완료 후 큰 참고 이미지 캐시를 해제하고 배치 종료·실패 후에도 편집 모델 메모리를 해제합니다. 상태 조회의 일시적 timeout/연결 오류는 같은 prompt ID로 다시 확인하며 생성 요청을 중복 제출하지 않습니다. 기존 개인 3개/전체 20개 한도를 사용합니다. 일반 결과 목록에는 중간 작업을 노출하지 않습니다.
- 기준 원화와 포즈 기록은 `data/pose-motions/<task>/`, 생성 프레임은 `data/frame-workspaces/<id>/`. `frame_workspaces`/`frame_versions`에 최종 완성 배치만 등록합니다. 생성 자식 이미지 폴더는 처리 후 정리합니다.
- 묶음은 소유자/관리자만 생성할 수 있습니다. 직접 업로드한 묶음 없는 작업도 지원합니다. 프레임 편집기는 기존 승인 팀원 읽기/소유자 편집 정책을 따릅니다.
