# 캐릭터 작업실 · 세션 인계

## 사용자 흐름

메인 사이트 왼쪽 **캐릭터 작업실** (`/#/characters`)에서 캐릭터 이름으로 묶음을 만듭니다.

1. 대표 원화를 업로드하거나 연결한 이미지 결과의 **대표 원화로**를 누릅니다.
2. 기존 원화·스프라이트·리깅 결과를 **원화 / 그림체 참고 / 방향 / 동작 / 리깅**으로 연결합니다. 방향과 동작 이름을 함께 보관할 수 있습니다. 결과 상세의 **캐릭터에 연결**도 같은 기능입니다.
3. 이미지 결과의 **기본 그림체로 보관**을 누르면 기반 그림체·추가 그림체·설명·해상도·기본 생성 설정을 묶음에 보관합니다. 원본 이미지나 마스크 데이터는 설정에 넣지 않습니다.
4. **원화·스프라이트 만들기 / 동작 만들기 / Live2D 만들기**로 이어갑니다. 생성 화면 상단에서 연결 대상이 보입니다. **대표 원화 가져오기**, **보관한 그림체·세팅 적용**을 명시적으로 눌러 가져옵니다.
5. 해당 캐릭터를 선택한 상태로 새로 생성하면 결과가 자동 연결됩니다. 선택을 비우면 연결하지 않습니다.
6. 연결한 스프라이트의 **프레임 편집**으로 들어가면 같은 묶음에 수정본도 모입니다. [프레임 편집 안내](FRAME_EDITOR.md).

그림체 참고 분류는 참고 결과를 모으는 용도입니다. 임의 참고 이미지의 화풍을 모든 모델에 자동 이식하는 기능은 아닙니다. 실제 생성 설정 재사용은 기존 생성기가 지원하는 그림체·설정 범위입니다. 8방향 연결은 결과 정리 기능이며 8방향 일관성 생성 완성을 뜻하지 않습니다.

**동작 만들기 → 세팅 모음**에서 걷기·달리기 영상 테스트 설정을 선택합니다. 생성 후 프레임 편집기에서 필요한 보행 구간을 잘라 새 버전으로 저장합니다. 프레임별 포즈 생성 실험은 종료했고 기존 결과 조회만 유지합니다. [프레임 편집·루프 정리](FRAME_EDITOR.md).

## 권한·데이터

- 승인된 팀원만 사용합니다. 팀원 묶음은 볼 수 있고, 소유자 또는 관리자만 변경·생성 연결할 수 있습니다.
- 묶음 이름·메모·기본 설정은 `characters`, 결과 연결은 `character_jobs` SQLite 테이블에 보관합니다.
- 대표 원화는 `data/characters/<id>/<random>.png`. 기존 원화 파일을 덮어쓰지 않습니다.
- 기본 설정 변경은 revision을 검사합니다. 작업 생성과 캐릭터 연결은 동일 DB 트랜잭션으로 수행하여 연결 실패 시 작업 등록도 되돌립니다.
- 기존 결과 삭제는 기존 갤러리 정책을 따릅니다. 묶음에서 **연결 해제**는 원본 결과를 삭제하지 않습니다.
- 생성 화면 선택은 탭 세션에 보관합니다. 화면에 선택 상태를 명시하며, 묶음 없이 생성할 수도 있습니다.

## 코드와 검증

- `character_studio.py`: 테이블 초기화, 묶음·원화·연결 API, 프레임 저장 API.
- `web/character-studio.html`, `web/assets/character-studio.*`: 작업실 UI.
- `web/assets/character-context.js`: 기존 생성 화면의 선택·원화/설정 가져오기, 생성 요청에 `characterId` 추가.
- `team_server.py`: 기존 이미지·영상·리깅 생성 트랜잭션 안에서 연결. 셸은 `web/team.html`, 결과 상세 연결은 `web/assets/results.js`.
- `test_character_studio.py`: 권한, 설정의 입력 데이터 제외, 생성 연결 롤백, 프레임 저장/복원/내보내기.
- `tools/test_character_studio.cjs` + `tools/serve_character_fixture.py`: 임시 SQLite·HTTP 서버로 브라우저 통합 검증. AI 완료만 명시적으로 모의 처리하며 운영 계정과 결과는 변경하지 않습니다.

서버는 기존 `start_team_tool_https` 경로로 시작합니다. DB 테이블은 앱 시작 시 추가됩니다. 새 프론트 파일은 기존 `/assets` 경로로 제공됩니다.
