# 스프라이트 프레임 편집 · 세션 인계

## 사용 방법

결과 상세의 **프레임 편집**, 또는 캐릭터 작업실에 연결한 스프라이트에서 엽니다. MiniMax 시트와 이미지 스튜디오의 4방향 시트를 지원합니다.

1. 편집할 원본·투명·루프 보정·재추출 시트를 선택합니다. 열·행·실제 프레임 수를 확인하고 **프레임 작업 만들기**를 누릅니다. 재추출 영상은 실제 디코딩된 프레임 수와 다를 수 있어 수동 확인이 필요합니다. 3열 시트처럼 셀 경계가 정수로 나뉘지 않으면 경계를 반올림해 자르고 투명 여백으로 셀 크기를 맞춥니다. 픽셀을 확대·축소하지 않습니다.
2. 아래 썸네일을 눌러 프레임을 고릅니다. **재생 / FPS / 확대·축소 / 맞춤**으로 확인합니다. 4방향 시트는 방향별 행 구간을 선택해 재생할 수 있습니다.
3. 잘 나온 프레임은 **좋은 프레임 고정**으로 잠급니다. **현재 프레임 외 모두 고정**도 가능합니다. 잠긴 프레임에는 생성·적용을 할 수 없습니다.
4. **B**로 고칠 부분만 칠하고 **E**로 마스크를 지웁니다. 마스크는 반투명 빨강입니다. 수정 요청을 입력하고 **칠한 부분만 수정 후보 만들기**를 누릅니다.
5. 앞 프레임 / 현재 원본 / 수정 후보 / 다음 프레임을 비교합니다. **이 프레임에 적용 · 새 버전 저장**으로 확정합니다. 닫으면 기존 프레임을 유지합니다.
6. **PNG·시트 ZIP**은 수정 PNG들, 균등 셀 시트, FPS·프레임 순서·방향별 구간 JSON을 내보냅니다. 갤러리 결과 상세에도 수정 시트가 추가됩니다. 원본 영상은 수정하지 않습니다.
7. 저장 버전을 선택해 **선택 버전 복원**하면 이전 프레임·고정·FPS 상태로 새 버전을 만듭니다. 이전 버전 파일을 삭제하지 않습니다.

단축키: **B / E**, **[ / ]** 크기, **Ctrl/Cmd+Z**, **Ctrl/Cmd+Shift+Z / Ctrl+Y**, **Space 드래그 / 휠 버튼 드래그**, **Ctrl/Cmd+휠**, **Ctrl+0** 맞춤, **← / →** 프레임 이동. 입력창에서는 편집 단축키를 가로채지 않습니다. 마스크 undo는 탭 메모리이며 저장 버전 복원과 별개입니다.

## 기본 흐름: 영상에서 반복 구간 고르기

키프레임 분류를 요구하지 않습니다. 결과 상세의 **반복 구간 고르기** (`/loop-editor?job=<id>`) 또는 스프라이트 생성 완료 화면의 동명 링크로 엽니다. 기존 프레임 편집기에서도 원본 영상으로 이동할 수 있습니다.

1. 원본 영상을 재생하고 슬라이더 또는 **← 이전 / 다음 →**으로 한 프레임씩 이동합니다. **지금 장면부터 / 지금 장면까지**로 시작·끝을 지정합니다. 소스 시트의 장수가 아닌 실제 영상 전체 프레임에서 고릅니다. 보라색 막대는 선택한 구간입니다.
2. 시작·끝 각각 **−1 / +1**로 조절하고 **선택 구간 반복 재생**을 봅니다. 우측은 **마지막 → 처음** 정확한 디코딩 프레임 두 장과 연결 직전·직후의 느린 재생입니다. 겹쳐 비교는 선택적으로 펼칩니다. 같은 자세여도 이동 방향이 다르면 튑니다. 양끝의 동일 자세 중복은 끝을 한 프레임 앞당겨 확인하세요.
3. 8/12/16/24장 또는 최대 64장 전체 중 선택합니다. 선택 구간보다 많은 장수는 만들지 않으며 실제 출력 장수를 표시합니다. FPS는 구간 길이에 맞춰 가장 가까운 정수로 계산하고 직접 바꿀 수도 있습니다. 화면에서 실제 출력 재생 길이를 확인하세요. 프레임 보간이나 AI 모션 추천은 없습니다.
4. 배경 유지 / AI 제거 / 단색 제거를 고르고 **이 구간으로 시트 만들기**를 누릅니다. 새 프레임 작업과 최초 버전으로 저장하고 ZIP·시트·부분 수정 링크를 표시합니다. 원본 영상과 기존 시트/수정본은 변경하지 않고, 갤러리 결과의 최신 수정 시트와 캐릭터 묶음에 연결합니다.
5. 입력창·버튼 밖에서 **Space** 구간 재생/정지, **←/→** 한 프레임 이동, **I/O** 시작/끝 지정. 모바일은 같은 기능을 버튼으로 제공합니다. 원본 영상 / 보정 전 영상 / 자동 루프 영상은 실제 존재할 때 선택할 수 있습니다.

`loop_editor.py`가 소유자/관리자 권한·완료 영상·경로·최소 2프레임·최대 64장·4MP 셀/64MP 시트를 검증합니다. GET `/api/jobs/<id>/loop-editor`는 프레임 시간표, `/loop-frame?frame=<0-based>&source=video`는 정확한 경계 PNG, POST `/loop-editor`는 `{source,start,end,count,fps,background}`를 받습니다. start/end는 0부터 시작하고 끝 포함입니다. 파일명·클립은 기존 프레임 작업 규칙을 따르며 샘플의 sourceFrame/sourceTime 및 videoRange를 animation.json에 보관합니다. 기존 시트 추출과 같은 락을 사용하고 실패 시 임시 작업 폴더를 정리합니다. 기존 영상의 디코딩·샘플링만 수행하며 생성 모델을 실행하지 않습니다. AI 배경 제거 선택 시에만 별도 배경 모델을 사용합니다.

## 기존 시트에서 구간 정리

1. 스프라이트 시트 도구의 **세팅 모음 → 걷기 / 달리기 · 영상 테스트 세팅 → 선택한 세팅 불러오기**를 사용합니다. FastH3 8스텝, 512×512, 3초, 12장 시트, 인간형, 강한 움직임, 오른쪽, 눈 깜박임 없음, 동작 여백 10%, 루프 켜짐, 자동 정규화·루프 구간 자동 선택 꺼짐입니다. 투명 시트/배경 제거·재현 번호 선택은 유지합니다. 적용 후 필요한 방향·프레임 수를 직접 바꿀 수 있습니다. 시트 프레임이 너무 적다면 생성 전 프레임 수를 늘리거나 기존 결과에서 재추출한 시트를 선택하세요.
2. 결과 상세의 **프레임 편집**에서 시트를 엽니다. 서 있는 앞부분 다음 프레임을 고르고 **현재를 시작으로**, 마무리 전 프레임을 고르고 **현재를 끝으로**를 누릅니다. 시작·끝 번호를 직접 입력해도 됩니다. 번호는 1부터 시작하며 끝 프레임을 포함합니다.
3. **선택 구간 재생**으로 루프를 미리 봅니다. 한 주기의 시작과 끝에서 같은 발이 비슷한 위치·방향·속도로 움직여야 합니다. 같은 포즈라도 움직이는 방향이 반대면 튑니다. 첫 프레임과 같은 끝 프레임을 중복해서 넣으면 잠깐 멈추므로 중복 여부도 확인하세요.
4. **선택 구간만 남기기 · 새 버전**으로 저장합니다. 실제 PNG 픽셀을 다시 그리거나 원본 파일을 지우지 않고 문서의 프레임 참조만 자릅니다. 고정 상태·FPS는 유지하고 클립 구간·열/행을 재계산합니다. PNG·시트 ZIP과 연결된 갤러리 수정본에도 적용됩니다.
5. **선택 버전 복원**으로 잘라내기 전 전체 구간을 복원할 수 있습니다. 마스크 undo와 별개입니다. 잘라내기는 모션 보간·발 접지·외형 흔들림을 자동으로 수정하지 않습니다.

## 처리 방식·한계

- Qwen Image 2.1 편집 모델로 마스크 주변을 크롭해 수정합니다. 기존 모델이 설치되어 있어야 합니다.
- **칠하지 않은 픽셀의 RGBA는 원본과 같으며, 마스크 안에서도 기존 알파를 그대로 보존합니다.** 얼굴·손·옷의 내부 디테일 보정용입니다. 실루엣 밖으로 팔을 새로 뻗거나 배경을 지우는 작업은 이 도구의 범위가 아닙니다.
- 한 번에 한 프레임을 수정합니다. 시간축을 학습한 일괄 애니메이션 보정은 아니므로 앞뒤 프레임의 표정·명암 연결은 비교하여 판단해야 합니다.
- 생성 후보는 자동 적용하지 않습니다. 작업 중 다른 버전으로 바뀌거나 프레임이 고정되면 이전 후보를 적용하지 않습니다. 생성 중에는 버전을 바꾸는 설정을 잠급니다.
- 같은 탭에서 페이지를 이동했다 돌아오면 **이전 수정 진행·후보 확인**으로 다시 확인할 수 있습니다.
- 시트 최대 64MP, 프레임 최대 64장, 한 프레임 최대 4MP. 마스크 undo 이미지 메모리는 약 64MB 기준으로 제한합니다.
- ZIP은 PNG와 JSON입니다. Unity AnimationClip을 자동 생성하는 전용 임포터는 포함하지 않습니다. 기존 Live2D 본·IK 타임라인과 별도 기능입니다.

## 구현

- `character_studio.py`: `frame_workspaces`, `frame_versions`. 작업 문서는 불변 PNG 파일을 참조합니다. 원본 PNG는 유지하며 변경한 프레임만 새 파일로 저장합니다.
- `data/frame-workspaces/<workspace>/`: `original-*.png`, `edit-*.png`, 요청 마스크, 후보 이미지/메타데이터. 원본 결과 폴더는 변경하지 않습니다.
- `/api/jobs/<job>/frames`: 시트 선택·분할, 기존 수정본 목록. `/api/frames/<id>`: 작업 조회.
- `/settings`, `/trim` (0부터 시작하는 start/end, 끝 포함, revision 필수), `/restore`, `/regenerate`, `/candidates/<task>`, `/apply`, `/sheet.png`, `/export.zip`가 프레임 작업 API입니다. 소유자/관리자만 쓰고 승인 팀원은 읽을 수 있습니다.
- `frame_edit.py`: FIFO 워커가 실행하는 단일 프레임 후보 생성. `jobType=frame-edit`이며 일반 작업·갤러리 목록에서 후보 자체는 제외합니다. 기존 GPU 대기 한도와 Comfy 프로세스 간 확인을 사용합니다.
- `web/frame-editor.html`, `web/assets/frame-editor.*`: 마스크/재생/고정/비교 UI.
- 적용·설정 저장·복원은 DB 트랜잭션과 revision 검사를 사용합니다. 결과의 `frameWorkspace`에 최신 시트 링크를 기록합니다. 수정 시트는 승인 팀원용 API로 제공하며 공개 영상 갤러리에 자동 게시하지 않습니다.

검증: `python -m unittest test_character_studio test_team_server`; `node tools/test_character_studio.cjs`. 실제 모델 확인은 `tools/verify_frame_edit.py`이며 `outputs/frame-edit-smoke-20261018/validation.json`에 마스크 밖 픽셀·알파 보존 검증을 기록했습니다. 운영 캐릭터나 결과는 덮어쓰지 않았습니다.
