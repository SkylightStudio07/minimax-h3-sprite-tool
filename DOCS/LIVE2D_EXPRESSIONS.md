# Live2D 표정 차분 편집 · 유지보수

## 사용 방법

자동 생성한 감긴 눈·입이 잘못된 경우에는 **눈·입·장비 다시 생성**에서 후보를 비교한 뒤 해당 슬롯만 교체할 수 있습니다. [재생성 가이드](LIVE2D_REGENERATION.md)를 참고하세요.

결과 갤러리 또는 내부 공유 링크의 **레이어 편집기**를 엽니다. 우측 **표정 차분**에서 바꿀 눈·입·눈썹 슬롯을 고릅니다.

1. 이름을 입력하고 **빈 차분 만들기** 또는 **현재 파츠 복제**를 누릅니다. 원본을 보관하려면 먼저 `원본 복제`라는 이름으로 복제하세요.
2. **P** 색상 브러시로 그리고 **E**로 지웁니다. 색상과 브러시 크기를 조절할 수 있고 펜 압력은 크기에 반영됩니다. **Ctrl+Z / Ctrl+Y**로 취소·재실행합니다. 기존 **B**는 생성 직후 픽셀 복원 도구입니다.
3. 원래 파츠를 25%로 겹쳐 위치를 참고할 수 있습니다. 실제 저장 픽셀에는 참고 이미지가 포함되지 않습니다. 참고를 끄면 실제 차분만 확인합니다.
4. 투명 PNG로 가져올 수도 있습니다. PNG는 전체 캔버스 크기 또는 선택 차분의 크기여야 합니다. 전체 캔버스 PNG는 해당 차분 영역만 잘라 사용하며 자동 확대·축소하지 않습니다. 차분 편집 영역은 대상 슬롯에 사방 24px 여유를 더한 범위입니다.
5. **선택 차분을 움직임에 적용** 후 **PSD와 패키지에 저장**을 누릅니다. 적용한 뒤 추가 편집은 저장하거나 적용을 취소한 후 진행합니다.

차분을 선택하면 기존 파츠 대신 미리봅니다. 감은 눈 차분은 눈을 뜬 파츠를 숨긴 상태로 참고합니다. 좌우 감은 눈 슬롯은 각각 작업하세요. 두 눈이 하나의 `eye_open_original` 슬롯이면 두 눈을 함께 그려야 합니다. 눈썹은 눈과 별도로 작업하는 것을 권장합니다.

보관한 차분은 레이어 패널에서 다시 선택하여 적용할 수 있습니다. 적용하지 않고 저장하면 보관만 하며 현재 캐릭터는 바뀌지 않습니다. 기존 원본은 작업 버전 v1에 유지됩니다.

## 저장·내보내기

- 차분은 `manifest.expressions[]`의 `variantOf` 레코드 및 `expressions/variant_*.png`에 보관됩니다.
- 적용은 기존 슬롯의 PNG·좌표·크기를 교체하고 `activeVariant`를 기록합니다. 기존 `id`, `fade`, `side`, 런타임 이름은 유지하므로 깜박임·입 움직임에 연결됩니다.
- PSD에는 적용된 슬롯과 숨김 상태의 이름 있는 차분 레이어가 포함됩니다. 차분 보관 레이어는 합성·웹 리거·Unity 프리팹에 중복 표시되지 않습니다.
- 편집기에서는 감은 눈·반대 입 상태가 기본 미리보기에서 숨겨집니다. PSD의 애니메이션 슬롯은 웹 리거가 깜박임·입 움직임에 사용하도록 포함합니다. 보관 차분은 선택으로 미리보며 표시 체크박스는 비활성화합니다.
- 갤러리·내부 공유는 저장 버전을 사용합니다. 공개 워크스페이스는 관리자 **공개본 갱신**이 필요합니다.
- Unity V1은 저장 ZIP을 사용합니다. V2는 저장 후 다시 생성해야 합니다. 모든 차분 PNG가 ZIP에 들어가지만, Unity 프리팹은 사이트에서 마지막으로 적용한 차분을 기존 슬롯으로 사용합니다. V1 프리팹은 보관 차분도 숨긴 상태로 넣으며, `RiggingV1Avatar.SetExpression("이름")`과 `ClearExpression()`으로 실행 중 바꿀 수 있습니다. V2는 아직 제공하지 않습니다.

## 구현 위치

- `web/rigging-editor.html`: 브러시 색상, 렌더링·직렬화 연결.
- `web/rigging-expressions.js`: 생성·복제·PNG·슬롯 교체, 참고 미리보기, undo/redo.
- `rigging_editor.py`: `variant_create`, `variant_png`, `paint`, `variant_apply` 검증 및 저장. 새 차분은 빈 상태로 보관할 수 있지만 빈 차분을 슬롯에 적용할 수는 없습니다.
- `team_server.py`: 차분 메타데이터 전달, `/rigging-expressions.js`. 기존 작업/내부 공유 revision API를 사용합니다.
- Unity importer: V2는 `variantOf` 보관 레이어를 프리팹에서 제외합니다. V1은 슬롯과 같은 순서로 숨겨서 넣습니다. V1 저장 패키지에 최신 importer를 포함합니다.

검증: `.venv\Scripts\python.exe -m unittest test_rigging_expressions test_rigging_editor test_team_server test_rigging_upscale`; Playwright가 있는 `NODE_PATH`에서 `node tools/test_rigging_expressions.cjs`. 테스트는 임시 작업과 모의 API를 사용하며 운영 결과를 변경하지 않습니다. 실제 Unity Editor 임포트는 별도 확인이 필요합니다.
