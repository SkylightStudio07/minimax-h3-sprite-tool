# 생성 화면 공통 작업공간 · 인계

2026-10-19. 이미지·스프라이트·리깅 생성 화면을 **왼쪽 설정 / 오른쪽 작업 화면**으로 통일했습니다. 기존 공통 테마와 계정·갤러리·공유 기능을 사용합니다.

## 사용자 흐름

- `#/create/image`: 왼쪽에서 작업 종류·설명·그림체를 고릅니다. 오른쪽은 생성 후보 목록과 선택 후보 크게 보기를 전환합니다. 후보 이미지를 누르면 크게 보기로 전환하고, 다시 누르면 기존 원본 이미지 뷰어를 엽니다. 이전·다음 후보, PNG·부분 수정·얼굴 보정·후속 도구 연결은 유지됩니다. 참고 이미지는 오른쪽 **원본 · 부분 수정**에서 확인합니다.
- `#/create/sprite`: 오른쪽 **동작 예시**에서 움직이는 도트/일러스트 샘플과 실제 시트를 비교한 뒤 **이 동작 설정 적용**을 누릅니다. 설정만 바뀌며 입력 이미지 교체·생성 시작은 하지 않습니다. 왼쪽 원본·설정·생성 버튼은 유지하며, 오른쪽 **내 입력 이미지 / 내 생성 결과**로 사용자 자료를 구분합니다. 생성 완료 시 내 생성 결과로 전환합니다.
- `#/create/rig`: 원본·생성 설정과 마스킹 입력 방식·도구는 왼쪽, 캔버스·가이드는 오른쪽입니다. 오른쪽 부위 선택 상자로도 눈·눈썹·입을 고릅니다. 생성 결과와 게임 스프라이트 관절점은 같은 작업 영역의 탭에서 엽니다.
- 700px 이하 도구 영역에서는 **설정 / 작업 화면**을 전환합니다. 전환·창 크기 변경으로 입력값과 캔버스를 다시 만들지 않습니다. 생성 완료 시 작업 화면으로 전환됩니다.
- 설정 목록과 작업 영역은 각각 스크롤됩니다. 생성 버튼은 별도 하단 영역이며, 상태 메시지는 작업 화면에도 표시합니다. 이미지 라이브러리는 기존 우측 서랍과 3×3 검색·페이지를 유지합니다.

## 구현 위치

| 파일 | 역할 |
|---|---|
| `web/assets/creation-shell.css` | 앱 셸 너비 제한 해제, 생성 화면 전용 전체 높이, 모바일 하단 메뉴 공간. 사이트 메뉴는 기존 248px 텍스트 목록 유지 |
| `web/team.html` | 이미지·스프라이트·리깅 라우트의 `body.creation-route`, iframe 높이 측정 예외. BGM은 기존 높이 측정 유지 |
| `web/assets/creation-workspace.js` | 기존 폼·업로드·캔버스·결과 DOM을 재배치. 결과/숨김 상태를 관찰하여 탭과 후보 선택 갱신 |
| `web/assets/creation-workspace.css` | 공통 분할 화면, 설정 스크롤·생성 버튼, 후보 목록/크게 보기, 모바일 전환 |
| `web/image-studio.html`, `web/index.html`, `web/rigging.html` | 공통 자산을 로드. 레거시 스프라이트·리깅은 기존 `embed-legacy.css`를 단독 페이지에서도 적용 |

재배치는 기존 스크립트와 캐릭터 묶음 모듈 **뒤**에 실행합니다. 노드를 복제하지 않으므로 기존 이벤트·캔버스·상태를 보존합니다. `id`를 바꾸거나 기존 노드를 `innerHTML`로 재생성하지 마세요. 이미지 생성 버튼은 고정 영역으로 이동하지만 `form="form"`으로 원래 폼의 검증·submit에 연결됩니다.

iframe 크기는 부모가 할당한 공간을 따릅니다. 생성 도구를 예전 `body` 높이 기반 자동 확장으로 되돌리면 독립 스크롤과 하단 버튼이 깨집니다. 홈·갤러리 등으로 나갈 때 `creation-route`를 제거합니다. 인증 해제 때도 제거합니다.

사용자 피드백으로 생성 화면에서 사이트 메뉴를 104px 아이콘 세로 목록으로 축소하던 스타일은 제거했습니다. 왼쪽 사이트 메뉴는 원래의 너비·텍스트·브랜드·계정 표시를 사용하며, 오른쪽 전체 작업 영역은 유지합니다.

이미지 부분 수정 캔버스는 실제 표시 사각형과 이미지 비율이 일치해야 합니다. CSS로 서로 다른 가로·세로 길이를 강제한 뒤 `object-fit`으로만 맞추면 마스크 포인터 좌표가 틀어집니다. 리깅 캔버스의 내부 해상도·확대 좌표는 기존 도구가 담당합니다.

## 보고 고르는 스프라이트 화면 · 2026-10-20

사용자 피드백에 따라 오른쪽 기본 작업 화면을 동작 예시로 바꿨습니다. 도트 대기/걷기/검 공격/푸른 검기, 일러스트 걷기/달리기 실제 생성 샘플 6종을 사용합니다. 샘플 캐릭터에서 만든 참고 예시이며 현재 입력의 실시간 미리보기 또는 정확한 결과 보장이 아니라는 점을 화면에 표시합니다. 수동 효과 데모를 AI 결과로 제시하지 않습니다. 푸른 검기 예시는 MiniMax 동작+효과 공동 생성 결과입니다.

- 카드 선택은 비교 화면만 변경합니다. 별도 적용 버튼을 눌러야 동작·효과·도트 출력·해상도·방향 등의 설정이 바뀝니다. 기존 업로드 이미지는 보존하고 생성 API를 호출하지 않습니다. 일러스트 걷기/달리기는 기존 FastH3 준비 상태를 확인한 뒤 적용하며, 미준비 상태에서는 설정을 변경하지 않고 안내합니다.
- 큰 예시와 시트 전환, 체크무늬/밝은/어두운 배경, 재생/정지, 도트/일러스트/이펙트 필터를 제공합니다. 동작 감소 환경은 처음부터 정지 포스터를 사용합니다. 작은 화면에서는 카드/비교 화면을 한 열로 줄이고 설정 적용 뒤 설정 탭으로 돌아갑니다.
- 왼쪽 원본/설정 구조는 유지하고 적용한 동작의 썸네일 요약과 예시 보기 버튼을 추가했습니다. 오른쪽은 동작 예시/내 입력 이미지/내 생성 결과를 분리합니다. 샘플 카탈로그를 보면서 새 원본을 넣어도 카탈로그 탭이 유지됩니다.
- `tools/build_sprite_examples.py`는 검토한 생성물의 표시용 복사본만 `web/assets/sprite-examples/`에 만듭니다. 원본 작업 메타데이터·ZIP·프롬프트 기록은 공개하지 않습니다. 실제 예시 미디어와 설정은 catalog.json, 동작은 sprite-examples.js, 반응형 배치는 sprite-examples.css에서 관리합니다.

검증: 기존 sprite-combat 폼 검사와 새 `tools/test_sprite_examples.cjs`에서 실제 폼/에셋 시작/공통 작업공간/새 예시 JS를 JSDOM으로 실행했습니다. 6종 미디어 존재·탭 기본값·필터·재생 제어·감소된 동작 환경·시트 전환·설정 적용·엔진 게이트·입력 이미지 보존·생성 호출 없음까지 통과했습니다. 테스트용 jsdom@26.1.0은 임시 도구 디렉터리에만 설치했습니다. 운영 HTTPS에서 JS/CSS/카탈로그/24개 표시 파일 총 28개 응답 200, no-cache를 확인했습니다. 정적 파일 변경이라 서버·ComfyUI 재시작은 하지 않았습니다. 운영 브라우저는 로그아웃 상태여서 내부 화면의 실제 렌더링/기하 검증은 수행하지 못했습니다. 인증을 우회하거나 새 계정을 만들지 않았습니다.


### 에셋 유형 선택 카드의 시각 예시 · 2026-10-20

첫 진입의 에셋 유형 카드 5종에도 썸네일을 붙였습니다. 일러스트/Live2D 정면은 기존 생성 프리뷰, 측면은 기존 오른쪽 치비 스프라이트의 정지 원본을 사용합니다. 탑다운/아이소메트릭은 생성 성공으로 오인하지 않도록 각각 머리 윗면/위에서 본 대각선과 바닥 격자가 보이는 로컬 SVG 시점 가이드를 사용하고 `시점 가이드`로 표시합니다. 라디오 + 이름/설명 + 이미지의 가로 배열로 좁은 왼쪽 패널에서도 높이가 과하게 늘지 않게 했으며, 전체 카드 클릭·키보드 포커스·방향 자동 설정은 유지합니다. 예시는 유형/시점 구분용이며 그림체를 변경하지 않는다는 문구를 추가했습니다.

공유 asset-start.js/css 변경으로 이미지 스튜디오와 스프라이트 만들기에 함께 적용됩니다. 5개 이미지 존재/장식 이미지 alt/라디오 선택/측면 오른쪽/Live2D 정면 고정과 기존 동작 예시 회귀 검사는 실제 JS의 JSDOM 실행으로 통과했습니다. 운영 HTTPS의 JS/CSS/이미지/SVG 7개 응답 200과 SVG MIME을 확인했습니다. 서버 재시작은 필요하지 않습니다. 실제 로그인 화면의 렌더링은 이번에도 확인하지 않았습니다.


### 에셋 유형에 따른 동작 예시 범위 수정 · 2026-10-20

측면 전투 예시 6종이 모든 에셋 유형에 노출되던 문제를 수정했습니다. 공유 asset-start가 유형 선택/확정/설정 복원 이벤트와 현재 선택값을 제공하고 sprite-examples가 이를 반영합니다. 측면(side)에서만 전투 미리보기·라이브러리·필터·설정 적용을 표시합니다. 미선택은 유형 선택 안내, 일러스트/Live2D/탑다운/아이소메트릭은 해당 카드의 예시 이미지와 설명을 보여 줍니다. 등록하지 않은 시점의 동작 예시가 있다고 주장하지 않습니다. 비측면으로 바뀌면 선택한 전투 예시와 큰 이미지 src를 지우고 직접 설정 적용도 차단합니다. 치비 공격 추천 버튼과 적용 썸네일도 비측면에서 숨깁니다. 측면 대기 예시를 적용할 때 에셋 유형이 일러스트로 바뀌던 연관 문제도 side를 유지하도록 수정했습니다.

검증: JSDOM의 실제 화면 스크립트 실행에서 미선택/4개 비측면 유형 숨김/측면 복귀/비측면 적용 방지/저장 설정 복원/유형 다시 변경/측면 대기 유형 보존과 기존 예시 기능을 통과했습니다. 기존 combat 폼 검사도 통과했고 운영 HTTPS의 변경 JS/CSS 3개 응답과 새 코드 제공을 확인했습니다. 정적 변경으로 서버 재시작은 하지 않았습니다.


### 측면 전투의 도트 / 일반 / 치비 분류 · 2026-10-20

측면 전투에서 예시가 혼합되어 보이던 목록을 도트/일반/치비의 세 카테고리로 분리했습니다. 카테고리 선택은 큰 비교 화면 위에 두고 도트를 기본으로 합니다. 도트 치비 4종은 도트, 기존 일러스트 걷기/달리기 2종은 일반으로 분류합니다. 도트가 아닌 치비의 검증된 동작 예시는 아직 없어 빈 상태 안내를 제공하며 다른 분류의 예시를 대체 표시하지 않습니다. 카탈로그 version 2에 category를 명시하고 생성 빌더도 갱신했습니다. 카테고리 변경은 표시만 바꾸고 생성 설정/입력 이미지는 적용 버튼 전까지 유지합니다. 비어 있는 카테고리는 이전 이미지 src/선택/적용을 지워 숨은 이전 예시가 적용되지 않게 했습니다. 치비 도트 공격 추천 버튼은 도트 카테고리에서만 보입니다.

검증: 실제 화면 JS의 JSDOM 실행에서 정확히 3분류, 기본 도트 4종, 일반 2종만 노출, 치비 빈 상태/이전 미리보기 제거/적용 방지, 다시 분류 선택, 기존 에셋 유형 범위/폼/엔진 게이트/입력 보존을 통과했습니다. 운영 HTTPS에서 새 category 카탈로그와 코드 제공을 확인했습니다. 서버나 ComfyUI를 재시작하지 않았습니다.
