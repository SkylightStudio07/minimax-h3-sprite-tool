# 레이어 편집 중 Live2D 미리보기

2026-10-19. 결과 또는 내부 공유 링크 → 레이어 편집기 상단 **Live2D 미리보기**에서 엽니다. 데스크톱은 편집 캔버스 옆, 좁은 화면은 아래에 표시합니다. 닫으면 플레이어와 WebGL 리소스를 해제합니다.

- 지우개·복원·색상 브러시를 놓거나, 순서·표시 상태를 바꾸거나, 취소·다시 실행하면 약 0.65초 후 현재 레이어를 반영합니다. **지금 반영**으로 즉시 갱신할 수도 있습니다.
- 깜박임·입 움직임·대기 동작, 일시정지, 휠 확대·드래그 이동을 지원합니다. 같은 크기에서 갱신하면 플레이어 확대·이동 상태를 유지합니다.
- 보관한 표정 차분을 선택하면 해당 슬롯에 임시 대입해서 미리 봅니다. 실제 결과물에는 **선택 차분을 움직임에 적용 → 저장**해야 반영됩니다.
- 미리보기는 자동 저장하지 않습니다. 갤러리·내부 공유·PSD에 남기려면 **PSD와 패키지에 저장**을 누릅니다.
- 이 미리보기는 기존 PSD 플레이어의 자동 움직임을 재현합니다. 편집한 본·IK·타임라인 동작은 **포즈 테스트**에서 확인합니다.

## 구현

- `web/assets/rigging-live-preview.js`: 기존 캔버스를 분할 화면으로 감싸고 `updateActions`, `updateSelection`, `load` 뒤에 갱신을 예약합니다. 현재 `parts` 순서·픽셀·좌표로 PSD 구조와 같은 메모리 객체를 만듭니다. 숨겨진 감은 눈/입 차분 슬롯은 런타임에 유지하고 보관 차분은 제외합니다.
- `web/assets/rigging-live-preview.css`: 분할 화면과 작은 화면의 헤더 배치.
- `web/rigging-editor.html`: 위 CSS·JS를 기존 편집 모듈 뒤, 초기 `load()` 앞에 로드합니다.
- `vendor/Anime2.5DRig/lib/app.js`: 같은 출처 iframe의 `editor=1`일 때만 `window.spriteEditorPreview.load/options/state`를 노출합니다. `Rigger.buildRig → applyRig`를 그대로 사용하며 저장 PSD를 로드하지 않습니다. 일반 플레이어의 로딩은 유지됩니다.
- 내부 공유에서는 기존 `/share/rig/<token>/player?editor=1` 경로를 사용합니다. 새 권한이나 서버 API는 추가하지 않았습니다.

레이어 재구성은 CPU·GPU 작업이므로 매 포인터 이동마다 실행하지 않습니다. 고해상도·많은 레이어는 장치의 기존 WebGL 크기·메모리 제한을 적용받으며 실패는 미리보기 상태줄에 표시합니다. 편집 내용은 유지됩니다.

## 검증

`NODE_PATH`에 Playwright 설치 경로를 지정하고 `node tools/test_rigging_live_preview.cjs`를 실행합니다. 실존 생성물의 레이어 PNG를 읽고 API는 격리하여 생산 작업을 수정하지 않습니다. Chrome WebGL의 실제 움직임, 저장 전 지우개 픽셀/표시 변경과 취소, 편집 캔버스 불변, 일시정지, 닫기, 내부 공유의 PSD 요청 없음, 작은 화면, 서버 쓰기 없음 등을 확인합니다.
