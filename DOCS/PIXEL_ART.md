# 로컬 픽셀 아트 · 설치와 인계

2026-10-19. 이미지 스튜디오 **픽셀 아트** 작업을 추가했습니다. 외부 PixelLab API는 사용하지 않습니다. 생성은 기존 로컬 ComfyUI/FIFO 대기열에서 실행합니다.

현재 작업 방향: 사용자가 768px 화풍 변환 실험을 원하던 아니메 스타일로 평가하지 않아 해당 방향은 중단했습니다. 이후에는 사용자가 받아들인 픽셀 캐릭터·영상 후처리 결과를 기준으로 윤곽·팔레트·무기 형태·프레임 일관성을 개선합니다. 아래 아니메 실험 기록은 채택한 제작 경로가 아닙니다.

## 조합 선정

- 기본: 공식 **SDXL Base 1.0 + 0.9 VAE** 체크포인트, `nerijs/pixel-art-xl` LoRA 강도 1.0 고정. 30스텝 / CFG 7 / Euler ancestral을 초기 실험값으로 사용합니다.
- 제작자 설명은 **refiner 미사용**, **0.9 또는 fp16 수정 VAE**, **최근접 8배 축소**를 권장합니다. LCM을 추가하는 고속 조합은 이번에 사용하지 않았습니다.
- 기반 모델 약 6.94GB + 픽셀 LoRA 약 171MB, 총 **7.11GB(약 6.62GiB)**입니다. 추가 모델 다운로드 후 SHA256 검증과 원자적 파일 이름 변경을 완료해야 준비됨으로 표시합니다.
- Pixel Party XL은 모델 카드에 호스팅 금지 문구가 있어 서비스 기본 후보에서 제외했습니다. Pixel Art Diffusion XL은 제작자 설명과 API의 상업·호스팅 조건이 더 제한적이라 제외했습니다. 승인 요청이나 우회 다운로드를 진행하지 않았습니다.
- 출처: [SDXL Base](https://huggingface.co/stabilityai/stable-diffusion-xl-base-1.0), [Pixel Art XL](https://huggingface.co/nerijs/pixel-art-xl). 각각 CreativeML Open RAIL++-M / CreativeML OpenRAIL-M 표기. 이용 조건은 `DOCS/model-licenses/pixel-art-xl/`의 원문·파일 해시를 참고하세요.

## 사용자 기능

1. 이미지 스튜디오 → **픽셀 아트**.
2. 캐릭터 전신 / 소품·자유 구도와 설명을 고릅니다. 새로 만들기 또는 참고 이미지 변형을 지원합니다.
3. 최종 **64·96·128px**, **16·32·64색 또는 제한 없음**을 고릅니다. 생성용 캔버스는 96px 출력에서 768px, 64·128px 출력에서 1024px 정사각형입니다. 64px 출력도 SDXL 구도를 유지하도록 1024px에서 생성합니다.
4. 후보를 비교해 실제 도트 크기 PNG를 다운로드합니다. 8배 최근접 확대 미리보기와 도트 정리 전 이미지도 보존합니다. PNG를 Aseprite에서 열어 직접 다듬습니다. `.aseprite` 레이어·프레임 자동 분해는 제공하지 않습니다.

색 수 제한은 투명 배경을 제외한 한 이미지의 팔레트에 적용합니다. 배경 제거는 선택 사항입니다. 캐릭터는 기존 로컬 Anime ISNet, 소품은 테두리와 연결된 단색 배경 제거를 사용합니다. 캐릭터 AI 마스크가 비어 있거나 대상을 거의 지우면 단색 제거로 재시도합니다. 이후 최종 최근접 축소·알파 이진화·팔레트 정리를 수행합니다. 배경과 대상이 구분되지 않으면 투명 결과로 표시하지 않고 원본을 보존합니다. 참고 이미지는 비율을 유지해 흰색 정사각형 캔버스에 배치합니다. 정체성 보존을 보장하지 않습니다.

픽셀 조합에서 추가 화풍·관절 포즈·얼굴 보정·고해상도 2차 생성·부분 인페인트·4방향 시트는 거부합니다. 결과의 **원본 참고로 다시 만들기**는 같은 픽셀 설정과 후보를 참고 이미지로 전달합니다. 다방향·애니메이션은 이번 범위가 아닙니다. 기존의 도트풍 4방향 시트 실험과 별도입니다.

## 코드

- `image_pixel.py`: 모델 허용 목록, 입력 검증, 비율 유지 참고 캔버스, 최종 픽셀 변환.
- `image_engine.py`: `pixel-art-xl` 등록, 고정 LoRA 워크플로(Windows ComfyUI 파일 목록과 일치하는 경로 표기), 출력 크기·버전 메타데이터, 최종 도트·확대 미리보기·정리 전 파일 저장.
- `team_server.py`: 기존 완료 작업의 허용된 이미지 경로에 `beforePixelUrl`, `pixelPreviewUrl` 추가. 픽셀 결과는 일러스트 얼굴 보정 API에서 거부.
- `web/assets/image-pixel.js/.css`: 전용 설정과 설치 상태 안내. 기존 `image-workspace.js`와 작업 탭·복원 연결.
- `web/assets/image-studio.js`, `results.js`: 도트 미리보기의 `image-rendering:pixelated`, 픽셀 후보에서 일반 얼굴 보정 버튼 제외.
- `tools/download_pixel_models.py`: 고정 revision/size/SHA256을 가진 `files.json`에서만 다운로드. 4개 세그먼트 병렬, `.download` 파일 검증 후 게시. 동일 작업을 중복 실행하지 마세요.

다운로드는 별도 숨김 프로세스로 실행했습니다. 로그는 `outputs/pixel-model-download.stdout.log`, `.stderr.log`. 다운로드 진행 상황을 계속 폴링하지 않습니다. 끝난 뒤 다음 작업에서 파일·해시를 확인하고 실제 GPU 품질을 검증합니다. 모델 목록을 로드한 페이지는 다운로드 완료 후 새로고침해야 합니다. ComfyUI의 체크포인트/LoRA 목록에 새 파일이 나타나면 엔진 재시작은 필요하지 않습니다.

## 실제 GPU 검증 · 2026-10-19

`tools/verify_pixel_art.py`에서 사이트의 `validate → run_job` 처리로 세 사례를 생성했습니다. 생산 갤러리는 수정하지 않았습니다. 모델 두 파일의 SHA256과 실제 ComfyUI 파일 목록도 확인했습니다.

| 사례 | 실제 출력 | 표시 색 수 | 배경 제거 | 시간 |
|---|---|---|---|---|
| 설명으로 캐릭터 생성 | 128×128 | 32 | Anime ISNet | 24.42초 |
| 포션 소품 생성 | 64×64 | 16 | 테두리 연결 단색 제거 | 24.25초 |
| 후드·코트 원화 변형 | 96×96 | 32 | Anime ISNet | 16.86초 |

세 사례 모두 실제 출력 크기, 최종 알파 0/255, 색 수 상한, 배경과 대상 픽셀 존재를 확인했습니다. 기록과 비교 화면은 `outputs/pixel-art-test-20261019/results.json`, `preview.html`, `comparison.png`입니다. 소품의 64px/16색·64px/32색·128px/64색은 같은 생성 이미지에서 출력 설정만 바꾼 비교도 제공합니다.

실제 시험에서 발견한 문제를 수정했습니다.

- Windows ComfyUI의 LoRA 이름은 `pixel\\pixel-art-xl.safetensors`이므로 OS 경로로 변환해 전달합니다.
- 64px용 512px 생성에서는 포션을 여러 패널로 그렸습니다. 64px도 1024px에서 생성하도록 하고, 시트·격자·비교·다중 물체 지시를 네거티브에 추가했습니다. 수정 후 한 개의 포션을 확인했습니다. 모든 프롬프트의 단일 물체를 보장하지 않습니다.
- 캐릭터용 배경 모델이 포션을 전부 지웠습니다. 소품은 단색 배경 제거로 처리하고, 비어 있는 결과·대상을 거의 지운 마스크는 투명 결과로 게시하지 않도록 검사합니다.

판정: 정지 도트 **초안**으로 사용할 수 있습니다. 64px/16색에서는 금속 테두리·얼굴·코트 장식이 손실되므로 세부 묘사는 128px/32~64색이 낫습니다. 발 모양·무기 각도, 남은 바닥 그림자, 그림체와 캐릭터 동일성은 Aseprite 등에서 검수·수정해야 합니다. 이 세 사례만으로 애니메이션·방향 일관성이나 PixelLab 수준의 품질을 검증한 것은 아닙니다.

## 픽셀 애니메이션 · 독립 실험

`tools/verify_pixel_animation.py`는 위 검증의 `knight-128/image-1.png`를 공통 외형 기준으로 사용합니다. 실제 128px PNG를 최근접 6배로 확대해 Qwen Image 2.1 편집 모델에 전달하고, 각 프레임의 COCO-18 뼈대를 두 번째 참고 이미지로 제공합니다. 네 프레임은 정면 보행의 좌우 접지·통과 포즈입니다. 매번 같은 원본을 참조하며 이전 생성 결과를 다음 외형 기준으로 사용하지 않습니다.

- **저해상도 전용 애니메이션 모델이 아닙니다.** 768px 이미지 편집 후 최근접 128px 축소, 이진 알파, 원본 32색에 대한 정확한 RGB 최근접 매핑을 합니다. 색상 매핑에는 디더링을 사용하지 않습니다. 색 수 고정이 캐릭터·장비 형태 보존을 보장하지 않습니다.
- 일반 Anime ISNet은 이 도트 기준 이미지를 거의 지워 시험에서 제외했습니다. 흰 배경에 연결된 단색 영역만 제거합니다. 흰 소품·닫힌 틈의 배경 잔여물은 여전히 검수 대상입니다.
- 생성 원본·포즈·워크플로 JSON·실행 기록을 모두 보존합니다. 기본 생성본에는 얼굴 덮어쓰기, 발 위치 자동 정렬, 프레임 보간을 하지 않아 실제 외형 흔들림이 비교 화면에 보입니다. 별도 **머리·얼굴 잠금 비교본**은 수동 지정한 원본 영역 `(53,17)-(76,39)`의 RGBA를 그대로 복사합니다. 자동 파츠 인식이 아니며, 검·몸통·다리의 변형이나 목 경계를 해결하지 않습니다. 원본/생성본/잠금본을 구분해 보여줍니다.
- 원본 도트의 팔레트 색을 재사용할 때 Pillow의 축약 색상 조회가 가까운 다른 색으로 바꾸는 것을 확인하여, 이 실험에서는 정확한 RGB 거리로 매핑합니다. 원본의 가시 픽셀 색이 그대로 통과하는 것을 확인했습니다. 이는 실험 내 처리이며 기존 정지 도트 생성기의 팔레트 구현은 변경하지 않았습니다.
- 생성은 `ensure_idle()`로 서비스와 GPU 대기열을 확인한 뒤 실행합니다. 생산 갤러리·프런트엔드·종료된 `/motion-studio`는 변경하지 않습니다. 추가 다운로드·Aseprite 설치·외부 API도 없습니다.

실행: `.venv\Scripts\python.exe tools\verify_pixel_animation.py --frames 4`. `--frames 1`로 첫 포즈만 시험할 수 있습니다. 완료된 프레임은 그래프 서명과 원본 PNG가 같으면 재사용합니다. 실행 중인 GPU 작업이 남아 있다면 중복 제출하지 말고 해당 `frame-XX-pending.json`의 promptId로 먼저 상태를 확인하세요.

결과 위치는 `outputs/pixel-animation-test-20261019/`입니다. `preview.html`에서 원본·생성 프레임·반복 재생을 비교합니다. `sprite-sheet.png`, 투명 APNG `animation.png`, 최근접 확대 무손실 `animation.webp`, 머리 잠금 비교본 `animation-head-locked.webp`, 생성/잠금 프레임 PNG·팔레트·시간 정보가 든 `pixel-animation-draft.zip`을 내보냅니다. 아직 편집 가능한 `.aseprite` 레이어 파일을 생성하는 기능은 없습니다.

### 네 프레임 실제 결과 · 2026-10-19

네 장 모두 생성 완료했습니다. 프레임별 생성 시간은 116.17 / 68.19 / 116.19 / 112.16초, 합계 412.71초입니다. 네 장 모두 128×128, 원본 팔레트 내 32색, 알파 0/255를 확인했습니다. PNG 시트 512×128, APNG·무손실 WebP 각각 4프레임, ZIP 17개 항목 무결성, 미리보기 파일 링크, 생성 후 빈 GPU 대기열을 확인했습니다. 머리 잠금 비교본은 지정 영역의 RGBA가 모든 프레임에서 원본과 정확히 같은 것을 검사했습니다.

시각 검토: 파란 머리·흰 스카프·남색 코트·갈색 부츠·검은 대체로 남고 다리 포즈가 변했습니다. 하지만 전체 생성본에서는 얼굴 방향·크기, 검 길이, 몸통 비율이 달라집니다. 발의 최하단은 원본 y=107에 비해 y=108 / 108 / 109 / 108입니다. 자세 전환과 발 접지가 불안정해 바로 사용할 완성 보행 루프로 판정하지 않습니다. 머리 픽셀 잠금으로 얼굴 변형은 막지만 검·팔·몸통·루프 연속성은 해결되지 않습니다. 다음 검증 대상은 장비를 독립 픽셀 파츠로 유지하고 팔·다리만 선택적으로 생성·수정하는 경로입니다. 전용 시간축 모델이나 프레임 간 보정 없이 동일 원화·뼈대·팔레트만으로 PixelLab과 같은 품질이 나온다는 근거는 아닙니다.

### V2 · 원본 파츠와 바닥 높이 보정

사용자의 추가 보정 요청에 따라 `tools/refine_pixel_animation.py`를 추가했습니다. **LoRA 학습·새 AI 생성은 하지 않았습니다.** 이전 네 장의 다리 포즈를 사용하고, 기준 도트에서 직접 지정한 마스크로 머리/몸통·양팔·검을 나눕니다. 이 한 캐릭터를 대상으로 직접 지정한 마스크이며 범용 자동 분절 기능이 아닙니다.

- 머리·몸통은 원본 색·픽셀을 유지하고 접지/통과 단계에서 전체를 정수 1px만 상하 이동합니다. 팔과 코트 끝은 행별 정수 픽셀 이동으로 작게 움직입니다. 회전 보간·페이드·색 혼합은 없습니다.

1. `baseline`: 이전 한 점 최근접 축소 결과를 그대로 읽습니다.

3. `temporal`: DIS 전후방 흐름의 일치·밝기 잔차를 검사한 영역에서 이전 프레임의 팔레트 색을 비교합니다. 현재 색에 거의 같은 비용으로 설명되는 이전 색만 유지합니다. 알파는 점유율 30~70%의 애매한 셀에서만 이전 증거를 사용하며, 명백히 새로 나타나거나 사라진 셀은 현재 증거가 우선입니다. 처리된 결과를 다음 프레임 증거로 누적하지 않습니다.
4. `head`: 시간축 결과에 원본 머리/얼굴/목의 수동 ROI를 KLT로 추적하여 정수 픽셀 이동으로 붙입니다. 몸통·다리는 기존 영상 동작을 유지합니다. 정면 V2처럼 전체 상체를 고정하지 않습니다.
5. `parts`: 머리와 원본 검날의 수동 마스크를 합성하는 **품질 미통과 실험본**입니다. 검 자체의 KLT는 73장 중 45장만 통과해 폐기하고, 손의 피부색 중심과 밝은 검날 방향을 관측해 원본 검날을 회전/이동하도록 바꿨습니다. 이 검출은 73장 모두 통과했지만 이것이 시각 품질 통과를 뜻하지는 않습니다. 검 주변 의상과 겹침, 원래 검 제거 경계와 잔여 픽셀 때문에 우선 후보로 추천하지 않습니다. 검 파츠를 제대로 합성하려면 검 뒤에 가려진 몸통/다리 복원도 필요합니다.

사용자 승인으로 스프라이트 만들기에 `공격 이펙트 · AI 생성`을 추가했습니다. `치비·도트 검 공격 추천 설정`은 측면/오른쪽, 기존 H3 일반 20스텝, 768×640, 3초, 30프레임, 여백 30%, 공격 후 원위치 복귀, 푸른 검기+금빛 타격 보통 강도를 적용합니다. 이 설정은 기존 입력 캐릭터로 동작을 만드는 경로이며 새 치비 원화를 생성하거나 정지 이미지 카탈로그를 바꾸지는 않습니다.

`combatEffect`(none/blue_slash/fire/impact/magic/custom), `effectStrength`, `effectDescription`을 서버에서 검증하고 실제 MiniMax 양성 프롬프트에 넣습니다. 효과는 AI가 동작과 동시에 생성합니다. 수동 좌표/프로시저럴 효과를 합성하지 않으며 **효과 별도 레이어는 없습니다**. 푸른 검기만 기존 AI 클립으로 검증했고 불꽃/타격/마법은 같은 경로의 설명 템플릿입니다. 크기 정규화는 효과 영역을 캐릭터로 오인할 수 있어 효과/도트 출력에서 생략하고, 오디오도 생성 그래프에서 제거합니다. 기존 무효과 기본 그래프는 유지합니다.

`pixelOutput`을 켜면 생성 해상도의 1/4로 배경 윤곽 정리 → 4×4 팔레트 투표 → 얇은 검 보존 → 선택형 시간축 색/알파 보정으로 내보냅니다. 캐릭터 입력색 최대 32색과 전체 영상의 새로운 유채색 최대 16색을 공유합니다. 캐릭터별 수동 얼굴/무기 마스크나 수동 색 매핑은 넣지 않았습니다. `pixelColorLock`으로 시간축 보정을 끌 수 있습니다. RGB 영상은 원본 그대로 보존하며 PNG 시트는 회색 배경/투명 버전, GIF는 기존 결과 다운로드에서 받습니다. GIF 기본 재생 시간은 실제 선택 프레임 간격을 따르고 FPS를 명시하면 사용자의 값을 따릅니다.

효과/도트의 투명 시트는 단색 배경 제거를 사용합니다. 인물 중심 AI 누끼가 검기·불꽃을 지울 수 있어 API에서도 이 조합의 AI 누끼를 거부하고 UI는 단색으로 전환합니다. 단순한 배경 또는 투명 입력이 필요하며 복잡한 배경의 일반 분리 도구는 아닙니다. 큰 효과의 프레임 경계 접촉은 결과 경고로 남깁니다. 잘림 자동 복구나 생성 성공은 보장하지 않습니다. 설정 저장·다시 만들기·결과 설정 라벨까지 연결했습니다.

검증: 기존 프롬프트/효과/GIF/API 회귀 검사, 새 잘못된 입력/그래프/실영상 인코딩/새 효과색/이진 알파/GIF 시간 검사, 실제 폼 JS의 DOM 모형 실행(추천값·제출·설정 복원·이전 설정 기본값), 기존 승인 AI 원본 73프레임을 운영 `run_job`과 새 후처리에 통과시킨 재생 검증(`tools/verify_sprite_combat_site.py`, `outputs/site-combat-check-20261020/validation.json`)을 사용했습니다. GPU 제출·업로드만 모형으로 대체했고 원본 AI 영상의 실제 디코드·도트화·시트·GIF는 수행했습니다. 새 GPU 재생성이나 실제 브라우저 렌더링 확인을 주장하지 않습니다.
