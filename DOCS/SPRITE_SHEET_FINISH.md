# 게임용 시트와 측정 세트

영상을 시트로 바꾸는 단계의 동작과 기준선입니다. 구현은 `sprite_finish.py`이고, 원본 시트와 투명 시트는 그대로 두고 게임용 시트를 추가로 만듭니다.

## 프레임 선택

새 생성 작업에만 적용합니다. 기존 결과의 재추출은 지금처럼 균등 추출입니다.

| 동작 | 방식 | `sheetSelection` |
|---|---|---|
| 반복 안 함 (공격, 시전, 피격, 사망 등) | 첫·끝·최대 도달·최대 속도 프레임을 고정하고, 약 절반은 시간 균등으로 예약한 뒤 놓친 자세가 가장 큰 프레임부터 추가 | `key-poses` |
| 걷기, 달리기 (반복) | 영상에서 보폭 주기를 찾아 한 주기만 사용. 주기가 분명하지 않으면 균등 추출 | `one-stride` |
| 그 외 반복 (대기 등) | 균등 추출 | `even` |

프레임 간격이 달라지므로 `sheetTimingMs`와 JSON의 `duration`에 프레임별 시간을 기록합니다. `one-stride`는 요청보다 프레임이 적게 나올 수 있습니다. 한 주기의 실제 프레임 수를 넘겨 만들지 않기 때문입니다.

## 게임용 시트

- `<action>_game.png`: 전체 프레임 공통 크롭. 프레임은 정수 픽셀로만 옮기므로 재샘플링이 없습니다.
- 지면 정렬은 idle, walk, run, attack, cast, hit에 적용합니다. 키의 5%를 넘게 뜬 프레임은 실제 도약으로 보고 옮기지 않습니다. jump, death, custom은 옮기지 않습니다.
- 반복 걷기·달리기는 영상 전체의 일정한 좌우 표류만 제거합니다. 공격의 전진은 건드리지 않습니다.
- `<action>_game.json`: TexturePacker JSON Hash 형식입니다. `anchor`/`pivot`은 발 기준점(`meta.pivotPixels`는 픽셀 값), `duration`은 밀리초, `animations`에 프레임 순서가 있습니다. PixiJS 8.6과 Phaser 3.87에서 읽어 프레임 좌표와 기준점을 확인했습니다. 어느 엔진이든 프레임별 `duration`은 재생 코드에서 직접 읽어야 합니다.
- 원본 캔버스에 닿는 프레임이 있으면 작업 경고로 알립니다.

## 프레임 수와 FPS를 지정한 시트

게임에 맞춘 프레임 수와 속도가 있으면 움직임 기준 선택 대신 연속 프레임을 그대로 씁니다. 모든 프레임 시간이 같고, JSON의 `meta.fps`에 속도를 적습니다.

- 사이트: 결과 상세의 **시트 다시 추출**에 프레임 수와 FPS를 넣고 배경 제거를 고릅니다. 값은 동작별로 브라우저에 기억합니다.
- 생성과 동시에: `sprite_motion_cli.py --frames 72 --fps 24`
- 이미 있는 영상에서: `python tools/sprite_sheet_cli.py --video idle.mp4 --output out --action idle --frames 72 --fps 24`

시트는 기본 8열이고, 한 변이 8192픽셀을 넘으면 열 수를 늘리거나 줄여 맞춥니다. 어떻게 해도 넘으면 경고를 냅니다. `--columns`나 **열** 칸으로 직접 지정할 수 있습니다.

## 측정

```
python tools/sprite_benchmark.py --output outputs/sprite-benchmark-<날짜>
```

GPU 없이 18개 완성 영상(캐릭터 6종의 대기·공격, 달리기·걷기, 치비 공격, 금발 대기)을 12프레임으로 처리합니다. 클립마다 `before_after.png`와 `game.png`, `atlas.json`을 남기고, 전체 수치는 `results.json`에 씁니다. 약 3분 걸립니다.

2026-11-09 기준선 (균등 추출·전체 캔버스 → 게임용 시트):

| 항목 | 이전 | 이후 |
|---|---|---|
| 일회성 동작의 최대 도달 자세 놓침 (7클립 평균, 낮을수록 좋음) | 16.7 | 0 |
| 일회성 동작의 가장 크게 놓친 자세 | 19.7 | 7.4 |
| 셀 대비 캐릭터 면적 | 33.5% | 80.4% |
| 평균 셀 넓이 | 280,348px² | 122,289px² |
| 지면선 흔들림 (키 대비 표준편차) | 0.26% | 0% |

측정으로 제외한 항목:

- 일반 시트 색 고정: 프레임 간 색 변화가 평균 ΔE 1.9, 최대 5.9로 작았습니다. 최대값은 공격 이펙트가 있는 클립입니다.
- 동작 간 키 통일: 같은 여백으로 만든 대기·공격의 키 차이가 최대 0.9%였습니다. 동작마다 여백을 다르게 주면 차이가 날 수 있습니다.
- 대기의 좌우 보정: 망토 자락을 발 위치로 읽어 몸 전체를 흔들었기 때문에 뺐습니다.

일반 AI 배경 제거(`ai`)는 영상의 폭발과 연기를 캐릭터가 아니라고 보고 지웁니다. `ai-soft`는 몸은 AI 결과를 쓰고, 그 밖의 효과는 단색 배경과의 색 차이로 투명도를 계산해 가장자리가 부드럽게 남습니다. 공격과 시전의 기본값이며, 배경이 단색이 아니면 일반 AI 제거로 처리합니다. 몸 안에서 배경색만 보이는 작은 구멍(몸 면적의 1% 이하)도 지웁니다. 효과가 캔버스에 닿으면 잘린 것이므로 작업 경고를 확인하세요. 공격과 시전은 기본 여백을 30%로 잡고, 무기가 뻗은 쪽에 여백이 더 생기도록 기준 이미지를 옮깁니다. 프롬프트에 "효과를 작게, 화면 안에" 같은 문구를 넣는 방법은 시험했지만 잘린 프레임이 3개에서 7개로 늘어 뺐습니다. 효과를 언급하면 모델이 더 크게 그립니다.

`pixel-walk` 갤러리 영상은 프레임이 중복된 재인코딩본이라 측정 세트에서 뺐습니다.
