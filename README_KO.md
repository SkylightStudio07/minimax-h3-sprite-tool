# MiniMax H3 Sprite Motion Tool

기준 이미지 한 장을 MiniMax H3 FL2VA에 넣어 캐릭터 동작 영상을 만들고, 선택한 수의 프레임을 PNG 스프라이트 시트로 패킹하는 Windows 로컬 도구입니다.

## 현재 구성

- H3 전용 ComfyUI 0.34 (`127.0.0.1:8189`)
- PyTorch CUDA 13.0 / RTX 50 계열 NVFP4 지원
- 16GB용 pruned INT8 diffusion + NVFP4 text encoder
- 기본 일반 20스텝, 선택형 4-step Turbo LoRA
- 세로/가로/정사각 해상도 프리셋, 5초, 기본 8프레임 시트
- 모델 파일은 저장소에 포함하지 않고 각 PC에서 별도로 다운로드
- 아래 속도 기록은 과거 Turbo 설정의 사례이며 현재 기본 일반 20스텝의 속도가 아닙니다.
- RTX 5060 Ti 16GB 실생성 검증 완료 (608x352, 124프레임, 약 57초)
- 세로형 Attack 실생성 검증 완료 (352x608, 124프레임, 약 47초)
- 원본 비율 고화질 Idle 검증 완료 (640x928, 124프레임, 약 164초)
- 화면 오른쪽 방향 고정 Attack 검증 완료 (640x928, 124프레임, 약 151초)

## 새 PC 설치

필요 환경은 Windows, Git, Python 3.12, NVIDIA GPU입니다. 모델을 포함해 약 50GB 이상의 여유 공간이 필요합니다.

위 설치는 NVIDIA 경로입니다. **시스템 RAM 32GB 이상을 실사용 권장 시작점으로 삼되, 정상 동작 보장은 아닙니다.** RX 9070 XT / Windows 11은 별도 [AMD 설치 가이드](AMD_INSTALL.md)를 사용하세요. AMD 경로는 현재 실기기 생성 미검증입니다.

1. 저장소를 clone합니다: `git clone <repository-url>`
2. `setup_windows.bat`을 실행해 ComfyUI, 가상환경, PyTorch CUDA 및 의존성을 설치합니다.
3. MiniMax H3 라이선스상 사용할 권한이 있는 경우에만 `download_h3_models.bat`을 실행합니다. 약 45GB를 다운로드합니다.
4. `start_idle_tool.bat`을 실행합니다.
5. 브라우저에서 `http://127.0.0.1:7866`을 엽니다.

모델, 가상환경, 생성 결과, 입력 이미지와 사용자별 라이선스 승인 마커는 `.gitignore`로 제외됩니다.

## MiniMax 라이선스 주의

이 저장소의 코드는 MiniMax 모델 가중치를 포함하지 않습니다. MiniMax H3 Community License의 지역 및 용도 제한을 직접 확인하고, 필요한 별도 승인을 받은 사용자만 모델 다운로드를 진행해야 합니다. 승인 확인 파일은 로컬에서만 생성되며 Git에 올라가지 않습니다.

## 사용

이미지를 넣으면 원본 종횡비를 유지하면서 H3가 요구하는 32픽셀 단위로 생성 크기를 자동 계산합니다. 기본값은 원본급 최대 1MP이며, 고화질 0.6MP, 표준 0.45MP, 빠른 테스트 0.25MP 및 직접 지정 프리셋을 선택할 수 있습니다. 예를 들어 `832x1216` 원본은 원본급에서 그대로 `832x1216`, 고화질에서 `640x928`로 계산됩니다.

H3 노드는 첫 프레임을 목표 크기로 강제 늘리고 마지막 프레임은 비율 유지 크롭하는 구조입니다. 이 도구는 업로드 전에 원본을 왜곡 없이 정확한 목표 캔버스로 맞춰 두 경로의 체형 변화와 프레이밍 불일치를 방지합니다. 실제 H3 입력으로 사용된 이미지는 각 결과 폴더의 `reference_prepared.png`에 함께 저장됩니다.

투명 PNG는 H3가 투명 픽셀을 검정 RGB로 처리해 배경이 흔들릴 수 있으므로, 입력 단계에서 균일한 중간 회색 매트로 합성하고 배경 고정 프롬프트를 자동 추가합니다.

지원 동작은 Idle, Walk, Run, Attack, Cast, Hit, Death, Jump, Custom입니다. Idle/Walk/Run/Jump는 기본적으로 처음과 끝이 연결되는 루프로, Attack/Cast/Hit/Death는 마지막 자세를 유지할 수 있는 1회 동작으로 설정됩니다. 체크박스로 어느 동작이든 루프 여부를 바꿀 수 있습니다.

`캐릭터 방향 고정`에서 입력 방향 유지, 화면 오른쪽, 화면 왼쪽, 정면, 후면을 선택할 수 있습니다. 측면 공격은 방향을 명시하면 H3가 캐릭터를 정면 연출로 돌리는 현상을 줄일 수 있습니다.

결과는 `outputs\results\작업ID`에 저장됩니다.

- `<동작>_raw.mp4`: MiniMax H3 원본
- `<동작>.mp4`: 캐릭터 크기를 정규화한 게임용 결과
- `<동작>_sprite_sheet.png`: 균등 간격으로 추출한 PNG 시트

세로형·정사각형 원본은 캐릭터 주변에 넉넉한 안전 여백을 두고 가로 캔버스에 배치하면 H3의 자동 확대와 전신 잘림이 크게 줄어듭니다. 후처리 정규화는 클립 전체에 동일한 변환을 사용해 호흡이나 바운스 동작과 루프 이음새를 보존합니다.

현재는 가로 캔버스로 바꾸기보다 **원본 비율 + 동작 여백** 옵션을 사용하세요. 아래 최신 기능 설명이 과거 실험 기록보다 우선합니다.

## 메모리

이 PC는 VRAM 16GB / RAM 32GB입니다. DynamicVRAM, smart-memory 비활성화, pinned-memory 비활성화를 적용했습니다. 생성 중에는 게임, 브라우저 탭, 다른 AI 모델 등 메모리를 많이 쓰는 프로그램을 닫는 편이 안전합니다.

## 최신 기능 사용 순서

### 1. 팀 서버 실행과 계정

- 일반 HTTP 로컬 사용: `start_team_tool.bat`. NVIDIA 단독 화면은 `start_idle_tool.bat`.
- AMD: `start_team_tool_amd.bat`. 두 백엔드를 동시에 실행하지 마세요.
- HTTPS 프록시 뒤: `start_team_tool_https.bat` 또는 AMD 전용 HTTPS 배치. 로컬 HTTP에서는 일반 배치를 사용하세요.
- 웹 주소: `http://127.0.0.1:7866`. ComfyUI 내부 포트는 8189입니다.
- 첫 관리자는 로컬 `data/admin-setup-code.txt`의 코드를 사용해 등록합니다. 코드·DB·세션 키를 Git에 올리지 마세요.
- 팀원은 가입 요청 후 관리자 승인이 필요합니다. 완성 갤러리는 로그인 없이 공개됩니다.
- 종료는 작업 완료 후 `stop_team_tool.bat` → `YES`. 팀 웹 서버만 종료하며 ComfyUI는 계속 남습니다. 다른 GPU 백엔드로 전환할 때는 기존 ComfyUI도 정상 종료한 뒤 실행하세요.

### 2. 이미지와 대상 유형

인간형 / 생물·괴물 / 부유 기계 / 지상 기계 중 선택합니다. 유형마다 호흡·부유·기계 관절 등 기본 동작과 구조 유지 지시가 다릅니다. 기계에는 눈 깜박임 지시가 들어가지 않습니다.

입력 이미지는 비율을 유지해 목표 크기에 맞춥니다. 투명 입력은 회색 배경으로 합성됩니다. **원본에 투명도가 있어도 생성 영상은 투명하지 않습니다.**

동작 여백은 없음·10%·20%·30%, 기본 10%입니다. 가로·세로 크기를 90%로 줄여 중앙 배치하는 10% 설정은 양쪽에 약 5%씩 여유를 만듭니다. 해상도를 키우지는 않으며 캐릭터 픽셀 크기가 줄어듭니다. 정규화가 다시 확대해 여백을 없애지 않도록 제한합니다. 이미 원본에서 잘린 부분은 복구되지 않습니다.

### 3. 동작과 프롬프트

- Idle: 영상 마지막까지 지속되는 대기. Walk/Run: 제자리 이동. Attack/Cast/Hit/Death/Jump: 공격·스킬·피격·사망·점프. Custom: 직접 설명.
- 움직임 강도는 약함·보통·강함, 기본 보통입니다. 강한 지시는 변형·잘림 위험도 늘릴 수 있습니다.
- 방향 고정은 원본 방향 또는 지정 방향을 유지하라는 지시이며, 결과를 보장하는 관절 제어가 아닙니다.
- 루프는 동일한 시작/끝 참조를 넣습니다. 죽음처럼 다른 자세로 끝나야 할 때는 꺼두세요.
- 세팅 모음은 선택한 뒤 ‘불러오기’를 눌러 적용합니다. ‘사용 안 함’을 불러오면 기본 동작 설명으로 돌아가지만 다른 옵션은 유지합니다.
- 조준 대기는 인간형·Idle·약함·원본 방향·깜박임 없음·루프를 적용합니다. 팔이 작은 호흡과 체중 이동을 보상해 조준선을 유지하도록 지시합니다.
- 대상 유형이나 기본 템플릿 변경 시 직접 쓴 설명이 교체될 수 있으니 확인창과 텍스트를 확인하세요.
- Seed를 같게 두면 설정 비교에 도움이 됩니다. 무작위성을 완전히 없애거나 결과를 보장하지는 않습니다.
- 네거티브는 기본 꺼짐인 실험 옵션입니다. 켜면 별도 CFG 경로와 추가 메모리·연산이 필요하고 형태/색 손상이 생길 수 있습니다.

### 4. 길이·모드·프레임 수

첫 테스트는 3초·빠른 해상도·Turbo 4스텝·시트 8장으로 시작할 수 있습니다. Turbo에서 변형이 심하면 같은 입력과 Seed로 일반 20스텝을 비교하세요.

일반 20스텝은 현재 기본입니다. 이 PC에서 832×1216, 5초 일반 생성은 약 24분 걸렸습니다. 해상도·길이·가속·오프로딩이 다른 기록을 단순 비교하지 마세요.

시트는 2~64장을 선택할 수 있습니다. 약 5초 영상은 모델 규칙상 124프레임이며, 시트는 그중 고른 이미지입니다. 시트 장수를 늘려도 AI 생성 스텝은 늘지 않습니다. 최대 8열로 패킹되며 루프는 마지막 중복 자세를 제외하는 방식으로 프레임을 고릅니다.

64장의 832×1216 이미지를 8×8로 배치하면 6656×9728입니다. 게임 엔진 최대 텍스처 크기에 맞춰 축소하거나 나누세요. Addressables 같은 비동기 로딩이 텍스처 메모리 부담을 제거하지는 않습니다.

### 5. 대기열·갤러리

생성은 한 번에 한 건씩 처리합니다. 개인 최대 3건, 전체 최대 20건의 활성 작업을 등록할 수 있습니다. 대기 작업은 본인 또는 관리자가 취소할 수 있습니다. 진행 중 생성은 함부로 서버를 꺼 중단하지 마세요.

갤러리는 페이지당 6개, PC 최대 3열입니다. 큰 시트 이미지는 목록에서 읽지 않고 영상은 재생 시 로딩합니다. 새 결과는 ‘새 결과 확인’으로 갱신합니다. 모바일에서는 열 수가 줄어듭니다.

본인 결과 또는 관리자는:

- **시트 다시 추출**: 기존 영상에서 2~64장 재추출. AI 생성 없이 기존 시트를 보존하고 별도 링크 추가. 이 기능에는 누끼가 적용되지 않습니다.
- **결과 삭제**: 갤러리와 공개 링크에서 제거. 파일과 기록은 서버에 복구용으로 남으므로 저장 공간을 비우는 영구 삭제가 아닙니다.

선택형 단색 누끼는 생성 설정에서 켭니다. 가장자리와 연결된 배경색만 제거하며 강도는 4~64입니다. 비슷한 색의 의상·머리카락이 손상되거나 닫힌 공간 배경이 남을 수 있습니다. 원본 시트와 별도 투명 시트가 저장되며 영상은 RGB 그대로입니다.

### 6. 출력과 문제 해결

작업별 `outputs/results/<작업ID>/`에 영상·시트·전처리 입력·`generation_prompt.json`이 저장됩니다. 프롬프트 기록으로 실제 Seed, 해상도, 모드, 여백 등 적용값을 확인할 수 있습니다.

| 증상 | 먼저 확인할 것 |
| --- | --- |
| 생성 버튼 비활성화 | 이미지 입력, 모델 준비, 라이선스 확인, ComfyUI 상태 |
| 너무 오래 생성 | 팀 대기열, 일반/Turbo, 해상도·길이, `logs/comfy.stderr.log`의 스텝 진행 |
| 메모리 부족 | 해상도·길이 축소, 다른 AI/게임 종료, 시스템 RAM과 VRAM 별도 확인 |
| 배경이 생김 | 프롬프트 제어의 한계. 동일 Seed로 비교하며 무조건적 해결을 기대하지 않기 |
| 캐릭터 잘림 | 동작 여백 증가, 큰 움직임 완화, 원본 이미지의 잘림 여부 |
| 형체·크기가 이상함 | H3 원본과 정규화 결과 비교, 대상 유형·입력 비율 확인 |
| JSON 파싱 오류 / 새 버튼 실패 | UI만 갱신되고 서버 코드가 재시작되지 않았는지 확인 |
| 갤러리 결과 안 보임 | 새 결과 확인, 현재 페이지, 작업 완료 여부 |
| 로그인 문제 | 계정 승인 여부, HTTP/HTTPS 실행 배치, 쿠키와 프록시 설정 |

코드 업데이트 뒤에는 진행 작업이 끝난 후 서버 재시작, 브라우저 새로고침을 하세요. 이미 등록된 작업에는 새 UI 옵션이 소급 적용되지 않습니다.

## 개발 확인과 백업

```powershell
.venv\Scripts\python.exe -m unittest test_background test_sprite_prompts test_team_server -q
```

AMD는 실행 파일을 `.venv-amd\Scripts\python.exe`로 바꿉니다. API/전처리 테스트 통과와 GPU 실생성 성공은 별도입니다.

백업은 서버 종료 후 `data/`와 `outputs/`를 함께 보관하세요. DB에는 계정·작업 정보가 있으므로 공개하지 마세요. 모델·가상환경은 재설치하고, 모델 권한 마커는 사용자별로 직접 확인합니다.
